DEMO 当前入口为 <http://127.0.0.1:8506>。排名、组合及“绩效与风险”读取原展示工作区已验证的结果和日期。日更统一使用下方原 PowerShell 入口；打开页面、查看股票详情或切换日期只读取已发布内容，不下载数据或执行交易。

在 PowerShell 运行：

```powershell

& "D:\us-tech-quant\更新今日推荐.ps1"

```

需要启动 DEMO 时，使用已有启动器指定端口：

```powershell

powershell -ExecutionPolicy Bypass -File "D:\us-tech-quant\apps\demo_console\start.ps1" -Port 8506

```

这一条命令会启动服务并自动打开浏览器；若该端口已有通过健康检查的 Streamlit 页面，则直接打开已有页面，不重复启动或结束进程。新启动服务时请保持终端窗口打开。端口被其他程序占用或服务未就绪时，会明确提示；可稍后重试或指定其他端口。自动化检查可加 `-NoBrowser` 禁止打开浏览器。

当前常规模拟执行窗口为 **美东 09:55–10:20（America/New_York）**；下午手动更新生成已完成交易日的合格输入，实际下单仍由原账户 owner 在窗口内核验。

需要 Moomoo OpenD 正常登录并连接到已有配置的端口。一次更新可能持续数分钟，进度会显示在页面或终端；重复提交由同一进程锁保护。MASSIVE 密钥已使用 Windows 当前用户 DPAPI 加密保存到 `cache_root/private_credentials/massive_api_key.dpapi`，程序在当前 Windows 用户下自动读取，无需每次输入，也无需在启动命令中填写密钥。

活动 HGB 政策由 `config/research_governance/selected_hgb_policy.json` 统一选择，DEMO、每日发布和原模拟组件读取同一配置。`RAW_TOP20_FROZEN_LEGACY` 使用原冻结优化器：新建仓候选为 Raw A2 Top20，已有持仓按旧优化器管理；`HGB_TOP20_RISK_R1` 使用 HGB Top20 并限制候选外旧仓不能增加。两者继续复用同一冻结 HGB 与风险模型。切换后只由新有效收盘信号生成后续调仓计划，已成交信号、账本与原开盘 0–10 分钟窗口保持原记录。

## 重复运行与失败恢复

同一条命令适用于每天更新和失败后重跑。新的完成交易日照常采集、核验并应用冻结模型；同一交易日已有接受来源时，先核对模型、生成时间、不可变来源 SHA、输入谱系、证券身份、复权收据和 HGB 特征，再恢复未完成步骤。已发布且通过原生产／读取器资格核验的 Raw／HGB 图表直接复用；基准用原固定 QQQ／SPY owner 核验并按需补取。恢复不重新采集股票池行情或推断 Raw 主排名，也不改原已成交信号和模拟订单；缺失的 HGB 目标仍由原隔离生成器应用冻结模型，已有合格目标和图表则直接复用。

这是恢复已接受输入的结果，不表示重新检查供应商是否修订同一天行情。如确实要重新采集同一天的新资料，显式运行：

```powershell

& "D:\us-tech-quant\更新今日推荐.ps1" -RefreshData

```

如果行情和复权收据已经保存合格，但输入路由工程问题造成当日证券被错误排除，可以显式重资格已接受的同日输入：

```powershell

Set-Location "D:\us-tech-quant"

& "D:\us-tech-quant-envs\us-tech-quant-main\Scripts\python.exe" -X utf8 -B -m scripts.daily_recommendation --execute --requalify-inputs

```

该模式仅适用于当前活动 LEGACY 政策和最近已完成交易日的已接受来源；复用原证券池、采集、原生发布证明和复权收据，经过全部原身份、日期、价格、121 日及特征资格门，再应用冻结模型。它不下载、不查询复权、不拟合，创建新的不可变 run，并以既有 `A2_OFFLINE_INPUT_REPAIR_V1` 收据绑定原来源，标为 `INPUT_ROUTING_REQUALIFICATION` 工程恢复；不会冒充当时新产生的历史 PIT 预测。原输入、旧报告和旧计划保留。输入绑定、资格或推断失败时不推进 `latest`；推荐 READY 后的独立图表失败仍明确记录 `completion=PARTIAL`，并保留已验证曲线。原已执行记录不允许借修复改写；同信号的未执行账户计划须由原账户 owner 另行严格核验，命令本身不下单。

默认入口只恢复已接受结果，`-RefreshData` 重新采集，`--requalify-inputs` 只修复已保存输入的资格路由；三者用途不同，离线模式不能与强制刷新或开盘图表模式混用。普通 MOOMOO 历史采集目前仍按原约 400 日请求范围复核，并非全流程只取新增日期；原生尾段补取和缓存复用另按已有收据执行。

绑定不一致时明确拒绝复用，不将旧来源冒充新结果。推荐来源接受后先保存恢复点。日更子阶段的原发布引用及开盘状态记录用于恢复；同日恢复报告存于原 recommendation run 的 recovery 子目录，终端显示其路径。恢复不覆写 canonical report／latest 与不可变推荐来源，保持交易原已接受来源 SHA 稳定。Raw 阶段失败仍尝试独立的 HGB 阶段；开盘输入失败则停止依赖它的图表回放。日志读取有大小和唯一终端结果约束，异常均记入原报告。重复调用不会重发旧订单，窗口内成交继续由原模拟账户 owner 核验。

原 PowerShell 日更在准备当前目标后、启动 MAIN 前，显式调用同一模块的 `--prepare-main-ca --expected-signal-date YYYY-MM-DD`。此阶段复用原范围、证券身份、RAW 和复权资格检查：已有合格当日回执时不查询，仅缺失代码才调用原 Moomoo `get_rehab` 并注册到当日来源定位；不拉取历史行情、不加载模型、不重放账户或下单。来源检查没有新增模型重放的内存门槛，原 MAIN 的资源与资格门仍保留。来源 `READY` 不等于 MAIN 发布成功；当期新增公司行动条款尚不获冻结引擎接纳时返回 `SOURCE_CA_TERMS_BLOCKED`，在模型加载前停止，保留已验证数据、目标及最后合格曲线，不把旧曲线标成当天结果。

报告 `status=READY` 只表示推荐输入及 Top20 已就绪。`completion.required_stages` 分别记录推荐、Raw 研究、HGB 目标与图表、基准；`completion.status=PARTIAL` 时命令返回失败码并显示具体分支，已资格验证的模拟目标仍可由原组件准备。股票池覆盖不足及 RX 冻结契约缺口保留在 `limitations`，不隐藏成“全部数据补齐”。完成日线与开盘研究、实际模拟成交分别注明日期，不提前补造收盘行情或成交。

原 PowerShell 入口默认启用 `--compact-output`，只精简终端结果，不改变原更新、校验、完成判据或保存的完整报告。直接调用原 CLI 时可用 `--execute --compact-output`；不加此标志仍输出完整结果。`full_report_ref` 优先引用本次恢复报告并绑定内容 SHA，原 `report_path` 和不可变推荐来源身份保留；当前报告引用失败时在摘要标明 full_report_ref_error，不回退到旧报告；原完成判据和退出码保持不变。

日常复用先看摘要的截止日、`completion`、覆盖缺口和原账户执行状态；仅对失败分支读取其报告。源码、输入及策略身份未变化且原校验通过时，无需重新做历史研究或全套工程测试。精简终端减少重复上下文读取，不代表减少模型计算、行情请求或实测内存峰值。

共同绩效刷新受阻时，原状态与精简摘要同时保留主错误及恢复错误。先按主错误定位失败步骤；新增两项诊断有明确长度限制和截短标记，原主错误与工作进程响应限制保留。

更新锁覆盖父任务全程。固定 provider 子进程由 Windows Job Object 在创建时归属父任务，父进程崩溃、超时或退出会结束所属子孙；无法建立归属时拒绝启动。模型和完整表格只在原短进程中存活。电脑及 OpenD 在线仍是开盘自动执行的前提。

开盘图表的外层任务也复用原有限 Job，最长 3600 秒；停止、关闭、取消、超时及父任务退出会回收自己创建的子孙进程。清理未完成时保留任务句柄，避免重复启动。原账户先完成停止操作，再等待图表清理；行情、推断和回放仍顺序执行。资源优化保留原数值运行环境，并继续严格验证已执行历史；不能因节省内存而放宽一致性检查。

原 `更新今日推荐.ps1` 在本次 HGB 目标与不可变推荐来源的日期、路径、SHA 和模型身份一致后，复用已在线模拟组件；组件离线时通过原启动器恢复已有账本与美东 09:55–10:20 普通窗口。在线实例的当前启停状态保留。独立研究图表受阻时会明确报错，已经资格验证的新目标仍可准备下一开盘。

保持已授权的模拟组件和 OpenD 在线，继续使用现有日更和调度入口。收盘后原日更生成 READY 信号；纸面仓与原 MOOMOO SIMULATE 账户按各自实际持仓和现金准备下一交易日计划。到达美东 09:55 后以第一份合格时价开始差额调仓，普通窗口为 09:55–10:20，报价、委托与成交记录实际时间。成交确认和估值更新继续由原账户 owner 负责。

## 从头重算每日 Top40

先完成目标交易日的数据更新，再运行独立的历史排名入口：

```powershell

Set-Location "D:\us-tech-quant"

& "D:\us-tech-quant-envs\us-tech-quant-main\Scripts\python.exe" -B -m scripts.research.a2.inference.historical_top40 --start 2023-01-03 --execute

```

默认截止到最近已完成的美股交易日，并读取当天更新流程保存的 READY 报告。`--source-report` 可指定已完成的采集报告，`--end` 可指定与该报告一致的数据日。不加 `--execute` 只校验输入并生成计划。相同 `--run-id` 可在输入契约和模型文件均通过哈希核对时继续该次运行；输入已变化时会明确拒绝复用。这个入口使用已有数据和收据，不负责联网补数。

每日选股池按既有机构注册表的季度有效期建立，只使用当日已披露且已生效的过去季度持仓。沿用原生效规则：**该季度所有适用的已登记机构完成披露后，以最晚实际披露日之后第 5 个美股交易日生效**，在下一季度生效前继续沿用上一份有效股票池，不提前使用尚未披露的日历上一季度数据。注册表中的 Situational Awareness 从 2024Q4 起适用，不能把今天的 25 家机构名单倒灌到更早季度。

模型在每一天自己的股票池和合格特征范围内重新预测、排名。Top40 是展示范围，不改变原 Top20 持仓规则。这个历史排名入口只生成排名；每日更新和下述绩效入口再读取排名，沿用原执行规则计算描述性绩效，不以收益选择模型或规则。原冻结历史、原模型与训练资料保持不变。

重算状态为 `PARTIAL` 时，表示部分股票或日期的输入仍有缺口；即使某日有完整 40 行，也不代表该日整个 13F 股票池都可计算。`WAITING_DATA` 日期没有可展示排名。复权按事件发生日处理，但今天补取的事件资料不等于已保存每个历史时点的供应商发布快照，报告会保留这个来源限制。

结果位于 `daily_root/A2_historical_top40/`：`latest.json` 指向本次运行，`runs/<run_id>/` 保存完整排名、Top40、逐日覆盖、股票池、模型及输入来源。期间页校验 Top40 和覆盖文件都属于同一次运行且 SHA256 匹配，并核对逐日年度模型身份。运行契约同时记录历史 QQQ 日期来源文件、冻结交易日历及规则文件的哈希，以及合并交易日集合的指纹，便于核对季度生效日和重算日期范围。

## 绩效与风险的自动更新

`更新今日推荐` 成功生成 READY 推荐后，自动更新 `daily_root/A2_updated_research/`。新运行的 `manifest.json` 绑定排名、逐日股票池覆盖、持仓、交易、净值、日期对应关系及全部输入哈希；只有完成校验的账本才发布为 `latest.json`。界面每次重绘重新读取这一指针，并按运行和哈希隔离缓存。

若隔几天才运行更新，程序会补算历史重算末日之后尚未保存的 2026 交易日，逐日使用当时已生效的 13F 池和同一个冻结模型，再连续重放绩效。补算记录标为描述性历史回放，不计作当时实际生成的每日推荐。中间日期不足 40 支合格股票或缺少可靠执行价格时，会明确提示，保留可验证的绩效截止日。

计算复用既有持续持仓回放引擎：Top20 等权多头、收盘信号在次一美股交易日开盘执行，换手率为实际交易金额除以交易前净值的一半，成本为 `0.5 × 实际交易金额 × 10 / 10000`。首个信号日从现金净值 1 开始，后续净值为交易后开盘估值；不在每次更新的末日强制清仓。原冻结展示保留自身原有口径。

缺少持仓或目标股票的执行价格、出现未解决的持仓公司行动时，绩效停在缺口前一个可验证交易日，不跨缺口拼接收益。排名覆盖不完整时保留 PARTIAL 状态，即使有完整 Top40，也不能理解为整个 13F 池都有数据。执行价格所需的开收盘校验与模型特征的 OHLCV 校验分别保留证据；前者合格不会使模型中原本不合格的股票获得选股资格。

单纯的大幅行情跳变不会自动当作拆股修正。对已核实的个别事件，保留原异常标记、供应商原始行情和复权资料、公开事件证据及复核记录；原价格和股份数量不因复核而改写。没有匹配证据的新异常仍会阻断该日起的绩效计算。

只用已补齐数据重建绩效、不重新联网采集时，可运行：

```powershell

Set-Location "D:\us-tech-quant"

& "D:\us-tech-quant-envs\us-tech-quant-main\Scripts\python.exe" -B -m scripts.research.a2.evaluation.demo_performance --historical-manifest "D:\us-tech-quant-daily\A2_historical_top40\latest.json" --current-report "D:\us-tech-quant-daily\A2_today_recommendation\latest.json"

```

新的描述性绩效包括已经暴露的历史区间，不构成未使用样本检验或实盘业绩。2026 年数据只用于已授权的固定规则计算和展示，不用于训练、调参或模型选择。

## 每次更新的内容

- 复用既有机构注册表，按查询季度的 `active_from_quarter`／`active_to_quarter` 确定适用名单，不要求历史季度固定有 24 或 25 家。SA 在适用起点前记为未开始披露，不计为缺失；已有两季披露也不代表之后自动停用。完整性核对当季基金身份集合，并记录当季名单哈希。证券身份资料及 Top100／保护 Top20／900 支上限规则保持原契约，检查 SEC 最新 13F 和修订申报。仅将已生效、身份可验证的股票纳入可计算范围，未验证身份保留为缺口；原冻结历史及模型不变。

- 按同一冻结 A2 模型“最新有可靠计算结果的 60 个交易日”统计 Top20 出现次数，再按 Top40 频率补充 Moomoo 优先名单。首次以已授权历史回放初始化，真实每日记录逐步替换相应日期。

- Moomoo 每周最多占用 300 支 K 线名额，按实时剩余额度安排；同周已占用股票可反复读取和补历史。优先名单之外的剩余额度继续补当前已验证 13F 股票池中的行情缺口，不因 Top20／Top40 名单不足 300 支而停止补数。额度未知时不盲目申请新名额。

- 采集时先用 MASSIVE 补 Top20／Top40 频繁名单以外的当前池股票，再继续按计划使用 Moomoo 和现有 Yahoo 适配器补数。保留原始响应、下载收据和来源；某个来源失败时继续其他已配置来源。

- 公开市场数据沿用已有采集模块及配置的数据集，更新时保留既有历史。A2 沿用冻结模型和原有特征计算；行情必须符合原有价格与复权口径，并覆盖目标交易日需要的连续历史。

## 如何判断结果可用

推荐日期使用日本时间；行情日期显示最近已完成的美股交易日。周末、假日或美股尚未收盘时，两者可能不同。

界面会列出 13F 季度、机构数、股票池规模、身份已映射数量、可计算数量、排除数量和报告位置。股票池与数据覆盖数量随更新变化，以本次结果为准。覆盖不完整时，Top20 仅代表本次可验证且满足计算条件的股票范围。

接口返回成功不等于可以进入模型。缺收盘价、行情日期落后、历史不足、身份未核实、原始价格衔接不一致或复权口径无法确认的股票，会在报告中保留缺口。MASSIVE 或 Yahoo 补充行情也必须通过与已有原始行情及 Moomoo 复权资料的校验，不用元数据价格填造 K 线。

若不足 20 支满足计算条件，页面显示等待数据；本次失败后不会把先前结果作为新结果展示。再次输入指令会重新尝试未完成数据。页面没有可读结果或读取文件失败时会给出提示，不阻塞其余展示模式。

输出位置由 `config/storage_paths.json` 指定。`daily_root/A2_today_recommendation/` 下：

- `latest.json`：当前结果。

- `runs/`：每次运行报告、输入来源和排除清单。

- `history/`：真实每日排名，供期间查询及后续 60 个可靠结果日的频率统计使用。

- `current_universe.json`：当前 13F 股票池引用。

开发检查：`python -B -m scripts.daily_recommendation` 只生成计划；加 `--execute` 才执行实际更新。

行情 SDK 连接复用现有的共享日更 quote owner：构造在自有 daemon 线程中完成，有限等待后仍按原流程查询和关闭连接。空股票池或空复权请求直接失败且不建立 SDK 连接；避免重连 Timer 在更新结束后阻止进程退出。模型、参数、交易窗口和账户规则不受影响。

Daily native updates now inspect internal gaps within the last 121 completed sessions as well as the final date. The bounded date projection combines the same-security frozen anchor and current native catalog. New securities start at their real observed first day. Original price, adjustment, identity and 121-session eligibility checks remain authoritative.

## QQQ／SPY 基准自动接续

每日原入口在同一更新锁内检查两只 ETF 的基准截止日，已到目标日直接复用。新日期优先使用经校验的 MASSIVE 原始开盘行情；只有已保存的 MASSIVE 接口明确失败时，才核验现有 MOOMOO RAW 数据。缺失的 ETF 最多一次两码、130 条常规时段日线请求，使用原 current-kline 采集器，不申请历史行情额度、不加入 A2 股票池。

备用来源必须绑定同一证券身份、USD、原响应和哈希，并与既有基准至少五个交易日及全部可比重叠开盘价逐项一致。原基准价格前缀保持逐项不变，新增日期在不可变 manifest 中明确记为 MOOMOO；后续 MASSIVE 合格时仍优先使用 MASSIVE。来源未知、价格冲突、缺目标日或权限拒绝保留原截止日和失败证据，不静默替换来源。

已停止交易的固定旧证券依现行备注避免重复采集；实际历史不足 121 个交易日的证券继续积累真实新日线，不作永久停用，也不放宽模型资格。RX 的每日当日聚类拟合仍受冻结边界阻断，行情补齐不会自动解除该限制。

当前采集备注由原日更入口读取 `daily_root/A2_today_recommendation/acquisition_notes_active.json`，它仅选择同一目录下 `acquisition_notes/versions/<SHA256>.json` 的不可变版本。新推荐来源只绑定实际备注版本的路径与哈希，不绑定会更新的指针；已接受来源和计划继续校验原版本。仅在指针不存在时兼容旧 `acquisition_notes.json`，指针存在但路径、大小、格式或哈希不合格时报告 `INVALID`，不回退、不跳过采集。备注仍须通过原证券身份及官方证据校验，并只在目标日严格晚于停用日期后生效。


已于 2026-10-09 获准的原 HGB 模拟仓每日自动接续由原组件持久化：优先现行普通窗口（2026-10-16 起美东 10:00–10:10），剩余固定目标自动补至日历收盘前十分钟；通常 50bp，仅真实一档价差可接受且总限 200bp，30 秒报价及 2% 偏离校验保留。一次授权从下一纽约日期生效，日更不生成新的人工续期；重启读取原授权、原批次、原账户和已成交进度。当前服务若被人工暂停，原日更仍保留暂停状态；正常恢复后沿用该长期规则。具体权限及失败余单处理见原[模拟组件说明](../apps/moomoo_trading_component/README.md)。

## 有限 MAIN 公司行动续接
